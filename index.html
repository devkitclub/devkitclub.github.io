10 concepts / 0 released

01ImportKitReliable CSV importsdata/validate first+

Map columns, preview errors, stage rows, process resumable batches, and export rejected-row reports

Failure to test
Kill the worker midway, resume from a checkpoint, and check for duplicate writes
Proposed boundary
CSV + PostgreSQL with React and FastAPI; one reference stack
02BackfillKitChange data without starting overdata/concept+

Cursor-based batches, persisted checkpoints, throttling, pause/resume, and before-and-after verification for live PostgreSQL systems

Failure to test
Concurrent writes, lock contention, and a restart between batches
Proposed boundary
PostgreSQL only, idempotent transforms, no automatic rollback of arbitrary logic
03WebhookKitAccept, persist, retry, replayinfra/concept+

Signature verification, a durable event inbox, deduplication keys, background retries, and an authenticated replay view

Failure to test
Duplicates, reordered deliveries, invalid signatures, and partial handler failures
Proposed boundary
One provider adapter; at-least-once processing with idempotent effects, not an exactly-once promise
04JobKitLong-running work with a visible stateinfra/concept+

Persistent job state, progress, cancellation, retries, a React dashboard, and permission-aware result downloads

Failure to test
A worker crash, duplicate delivery, cancellation races, and expired artifacts
Proposed boundary
One queue and database; tasks must be idempotent or explicitly tolerate repeated execution
05AuditKitWho changed what, and whensaas/concept+

Append-only audit events with actor and tenant context, redacted diffs, searchable history, scoped exports, and retention controls

Failure to test
Cross-tenant reads, missing actors, concurrent mutations, and secret redaction
Proposed boundary
Application-level history, not a compliance certification
06MeterKitLimits backed by a usage ledgersaas/concept+

Atomic reservations, usage events, credits, refunds, entitlement checks, and a customer-facing balance history

Failure to test
Concurrent decrements, duplicate usage, refunds, and billing-period boundaries
Proposed boundary
Usage and entitlements, not payment processing, tax, or accounting software
07ReleaseKitFrom green check to verified packageinfra/small experiment+

The smaller paid experiment: build/install smoke tests, versioning, changelogs, publish safeguards, and dry-run runbooks — a natural next step from RepoReady Lite

Failure to test
Broken metadata, version mismatches, missing registry credentials, and installation failures
Proposed boundary
Documented Python/npm configurations; publishing requires your own credentials and deliberate approval
08UploadKitResume the transfer, respect accessinfra/concept+

Chunked uploads, resumable sessions, private object storage, signed downloads, quota checks, and abandoned-upload cleanup

Failure to test
A disconnect mid-transfer, corrupt chunks, oversized files, and unauthorized downloads
Proposed boundary
S3-compatible storage, one frontend stack, bounded file sizes; no malware scanner in v1
09ReconcileKitMake differences explainabledata/concept+

Normalize source snapshots, classify mismatches, review discrepancies, and preview approved repair operations

Failure to test
Duplicate identifiers, currency precision, stale snapshots, and repeated repairs
Proposed boundary
One narrow domain; no autonomous high-risk financial changes
10SyncKitPick up where the API stoppeddata/later exploration+

Checkpointed initial and incremental pulls, cursor history, bounded retries, drift detection, and explicit deletion semantics

Failure to test
Rate limits, repeated pages, expired cursors, upstream changes, and outages
Proposed boundary
One maintained provider adapter and a deterministic mock API; higher connector upkeep

Before you start

Good to know before the first commit

Is RepoReady Lite really free?

Yes, the starter is open source under the MIT license and can be used and adapted for commercial projects under those terms. GitHub Actions usage follows your own GitHub plan

Do I need an account or API key?

You don’t need a DevKit Club account or API key, just a GitHub repository with Actions enabled and a Python or npm project with working tests

What setups are supported?

The Python starter uses pip and pytest; the JavaScript starter uses npm, a committed package-lock.json, and a non-interactive test script. Other package managers, monorepos, service containers, and deployment workflows need additional configuration

Check prerequisites ↗
Where can I get help?

Read the troubleshooting guide or open an issue with the relevant error and setup details. Remove credentials and private data before posting
